# 出題用サイト ─ Link！Like！ラブライブ！／蓮ノ空 クイズ大会

会場で司会・運営が操作し、プロジェクターに投影するクイズ出題サイトです。
デザイン提案（D案 リンクラ・ライク）をそのまま実装しています。
サーバーもビルドも不要で、HTML／CSS／JavaScript だけで動きます。

## 使い方

1. Google Drive の「出題用サイト_媒体」の中身（`第1回/` …）を `media/` に同期またはコピーする（命名規則は `media/README.md`）
2. ローカルサーバーで開く（下記）。ブラウザは Chrome 推奨
3. 第〇回を選ぶ → TOP でジャンルを選ぶ。右下の「全画面」で投影する

サイトはフォルダ名とファイル名から回・ジャンル・問題を組み立てるので、コードや設定の編集は不要です。

```bash
python3 scripts/serve.py 8765
# → http://127.0.0.1:8765/ を開く
```

`scripts/serve.py` は `python3 -m http.server` と同じフォルダ一覧を返しつつ、HTTP Range（動画のシークと、100 MB を超える解答動画をすぐ再生するために必要）と並行接続に対応し、`Cache-Control: no-cache` を付けて Drive で差し替えた媒体を再読み込みのたびに取り直す静的サーバーです（標準ライブラリだけ、pip 不要）。
`python3 -m http.server 8765 --bind 127.0.0.1` でも動きますが、動画のシークができません。
オプション：`python3 scripts/serve.py [ポート] [-b アドレス] [-d フォルダ] [-q]`。

`index.html` をダブルクリックして開いても動きますが、ブラウザによっては
動画・音声の再生が制限されるため、ローカルサーバー経由をおすすめします。

## 画面と進行

| 画面 | 進行 |
| --- | --- |
| 第〇回選択 | `media/` の回フォルダごとに1枚。出題済の記録は回ごとに別々に保存 |
| TOP | ジャンルフォルダごとのパネル。出題済の数と進捗バー。「この回の進捗をリセット」は確認ダイアログ付き |
| 楽曲・音声 | 1問＝3点／2点／1点の3クリップ。押すと再生、再生済は「済」。下部バーに停止・一時停止・進捗 |
| 楽曲・歌詞 | 3点→2点→1点の順に歌詞を表示 → 「回答を表示」 → 楽曲を再生 |
| 動画 | 初級1点／中級2点／上級3点。問題動画 → 「回答動画を再生」。「問題動画を最初から」で再生し直し |
| 文章（1枚絵） | 3点（問題のみ）→ ヒント1で2点 → ヒント2で1点 → 「回答を表示」（ヒント3） |

- 出題済の記録はブラウザ（localStorage）に回ごとに保存され、リロードや再起動後も残ります
- 記録の削除：TOP の「この回の進捗をリセット」（回全体）、音声画面の各行のリセットボタン（その問題だけ）
- 読み込み元：各回の `読み込み用ファイル.txt`（ローカルの `media/` に `python3 scripts/make_list.py` で生成。`drive/` には実行しない）。無ければサーバーのフォルダ一覧を使うので、生成しなくても動きます
- キーボード：`Space` 再生／一時停止、`Esc` TOPへ

## 画面サイズ

1440×810（16:9）で設計し、ウィンドウの大きさに合わせて全体を拡大縮小します。
1920×1080 のプロジェクターにそのまま収まります。

## 注意

- 音声・動画・画像は権利物のため `media/` 以下は Git に含めません（`.gitignore`）
- Web フォント（Noto Serif JP など）は、手元に保存していなければインターネット接続時のみ読み込まれます
  （保存の手順は「フォント」）。オフラインでは Mac 標準のヒラギノに置き換わります

## 媒体ファイルの置き場所（Google Drive）

音声・動画・画像は Git ではなく Google Drive の共有フォルダ「出題用サイト_媒体」で管理します。
`第1回/` の下に 11 ジャンルのフォルダと、問題（第N問）・級（初級／中級／上級）のフォルダまで作成済みです。
名前の規則は `media/README.md`、仕組みの説明は `docs/フォルダ連動の仕組み.html` を参照してください。

サイトにつなぐ方法は2つあります。

**A. Google Drive for desktop で同期する（会場 PC・開発 PC ともにこちらを推奨）**

1. https://www.google.com/drive/download/ から Google Drive for desktop を入れ、「出題用サイト_媒体」が見えるアカウントでログインする
2. プロジェクトのフォルダで次を1回実行する（同期フォルダを探して `drive` というリンクを作る。ストリーミング／ミラーのどちらの置き場所でも探す）

   ```bash
   python3 scripts/link_drive.py
   ```

3. サーバーを起動してブラウザで開く。以後、Drive 上の変更はページの再読み込みで反映される
4. オフラインでも動くようにする作業（「オフラインで使用可能」など）は会場準備で行う（「会場チェックリスト（後日）」）。それまで運営のフォルダはオンラインのまま使う

サーバーは Terminal（ターミナル）から起動してください。別の起動方法（アプリ内のプレビューなど）では Drive のフォルダを読めないことがあります（原因は未特定）。起動したら次で確認します。一覧（HTML）が返れば読めていて、404 などなら読めていません。

```bash
curl http://127.0.0.1:8765/drive/第1回/
```

Drive 上のファイルの大半は、クラウドにだけある占位ファイル（dataless）です。開いた瞬間に Drive が取りに行くので、初めての再生は待たされることがあります（動画は特に）。次のコマンドで事前に確認・取得できます。出力には答え（曲名など）が含まれるので、公開の場所には貼らないでください。

```bash
# サイトがこの回から何を読み取るか（問題の一覧・警告・パターン集計）
node scripts/check_media.mjs --base drive --round 第1回
# サーバー経由で、割り当てた全ファイルを 1 回ずつ取得する（Drive のキャッシュを温める）
node scripts/check_media.mjs --url http://127.0.0.1:8765 --check-files
```

**B. 手動でコピーする**

Drive から `第1回/` ごとダウンロードし、`media/第1回/…` となるように置く。更新のたびにコピーし直す必要があります。

サイトは `drive`（A）に回フォルダがあればそれを、無ければ `media/`（B）を読みます（`js/config.js` の `mediaBases`）。

## フォルダとサイトの連動について

サイトは「フォルダ名とファイル名」から画面を組み立てます。Google Drive そのものを直接読むわけではなく、
サイトを動かす PC の `media/` フォルダを読みます。Drive for desktop で同期していれば、Drive 上の変更は
数秒で PC に届き、サイトは次の読み込み時（ページの再読み込み、または回の選択画面の「フォルダを再読み込み」）に反映します。

### フォルダを変えると自動で変わるもの

| Drive（= media/）でする操作 | サイトの変化 |
| --- | --- |
| ジャンルのフォルダ名を変える（例：`楽曲・音声_イントロ_減点方式` → `楽曲・音声_サビ当て_減点方式`） | TOP のパネル名・カテゴリ・方式のチップが変わる |
| `第N問` フォルダを足す／消す | 問題数（0 / 6 の分母）と問題の行・カードが増減する |
| `第2回` フォルダを足す | 第〇回選択画面にカードが増える |
| ファイルを置く／消す（例：`音声1_ver3.mp3`） | 対応するボタン（1点問題 など）が押せるようになる／「なし」になる |
| 初級／中級／上級 のフォルダを足す／消す | 動画の級の段が増減する |

コードや設定ファイルの編集は不要です。

### 連動の範囲外・注意点

- **Drive の中身は PC に同期されている必要がある。** サイトが読むのは PC 上の `media/`。Drive だけを変えて PC が同期していなければ反映されません。
  会場では事前にフォルダを「オフラインで使用可能」にしておくこと（ネットが無いと未取得のファイルを開けません）。
- **出題済の記録はフォルダ名に紐づく。** 大会が始まってからジャンル名や回の名前を変えると、そのジャンルの「済」の記録は新しい名前には引き継がれません。名前の変更は大会前に済ませるか、リセットされてよい場合だけ行ってください。
- **並び順は名前で決まる。** Drive で見えている順ではなく、カテゴリ（楽曲・音声 → 楽曲・歌詞 → 動画 → 文章）、次に名前の順です。順番を指定したいときはフォルダ名の先頭に `01_` のような番号を付けます（番号は画面に出ません）。
- **名前の形は守る。** ジャンルは `カテゴリ_ジャンル名_方式`、問題は `第N問`、段階は `_ver1`〜`_ver3`、動画は `_問題`／`_回答`。形が崩れたフォルダも表示はされますが、種類をファイルの拡張子から推測するため意図と違う画面になることがあります。
- **「_」や「.」で始まる名前は無視される。** メモ用のテキストなどを置きたいときに使えます。

## 会場の準備

### フォント

会場がオフラインでも同じ書体で表示するため、ネットにつながるときに 1 回だけ次を実行して Web フォント（Noto Serif JP・Oranienbaum・Zen Kaku Gothic New）を手元に保存します。

```bash
python3 scripts/fetch_fonts.py            # fonts/ に woff2 と fonts.css を保存（取得済みはスキップ）
python3 scripts/fetch_fonts.py --dry-run  # 保存せず、内訳と保存予定だけ表示
```

`fonts/` は容量が大きいので Git には入れません（`.gitignore`）。無いままオフラインで開くと、Mac 標準のヒラギノで表示されます。

### 会場チェックリスト（後日）

今回は運営の Drive フォルダをオンラインのまま使います。次は会場に向けた準備のときに行います。

- [ ] Drive の「出題用サイト_媒体」を Finder で右クリック →「オフラインで使用可能」にする。`node scripts/check_media.mjs --base drive --offline-check` で未取得（dataless）が 0 になるのを確認する。運営がファイルを足すとオンライン中にしか落ちてこないので、当日にもう一度確認する
- [ ] Wi-Fi をオフ（Drive アプリも終了、Mac も再起動）にしてリハーサルする。サーバー起動 → `check_media.mjs --url` → 通しで再生。「オフラインで使用可能」が再起動後も効くことの確認になる
- [ ] `python3 scripts/serve.py 8765` を Terminal から起動する（会場の Mac に `python3` があること。node は不要）。起動したら `curl http://127.0.0.1:8765/drive/第1回/` で確認する
- [ ] URL とブラウザのプロファイルを固定する（`http://127.0.0.1:8765/` だけを使う）。出題済の記録は localStorage に入り、オリジン（`127.0.0.1` と `localhost`、ポート違いは別扱い）とプロファイルごとに別々なので、違う入口やシークレットウィンドウでは「済」が見えない
- [ ] ハードリロード（Cmd+Shift+R）で最新の JS・CSS と媒体を読み直す
- [ ] 投影：ミラーか拡張か、映像・HDMI の音声出力先、スリープと通知のオフ、Chrome のズーム 100%
- [ ] 進捗のリセット：リハーサルの記録を、TOP の「この回の進捗をリセット」で消す
- [ ] 予備コピー：`rsync -a drive/第1回/ media/第1回/` でコピーし、`node scripts/check_media.mjs --base media --round 第1回` でファイル数とサイズを `drive/` と突き合わせる。切り替えるときは `drive` リンクを外す（リンクだけを消す `rm drive`。`-r` や末尾の `/` は付けない）。切り替えを判断する担当を決めておく

## 開発者向け

- 設計の元資料：`docs/出題用サイト_デザイン提案_D案.pdf`（画面デザイン）、`docs/フォルダ連動の仕組み.html`（シート5 のフォルダ連動の読み解き。ブラウザで開く）
- 仕様書（Google スプレッドシート「出題用サイト_画面項目仕様書」）は運営チームから共有を受けてください（公開リポジトリのためリンクは載せません）
- 構成と約束ごとは `CLAUDE.md`、残作業は `PLAN.md` を参照
- 作業の流れ：作業ブランチを切り、Pull Request でレビューしてからマージする。ローダー v3 の作業中は、機能ごとのブランチ → 統合ブランチ `feat/v3` 宛ての PR → 画面が揃ったら `feat/v3` から `main` へ 1 つの PR（単独で `main` に入れると画面が壊れる）。`js/` か `css/` を触る PR は `index.html` の `?v=` を更新する
- コミットしないもの：`media/` 以下（権利物）、`drive` リンク、`fonts/`、`tests/expected.*.json`（いずれも `.gitignore` 済み）。実データのファイル名（曲名＝答え）はコード・テスト・文書・PR のどこにも書かない（テストはダミー名、例は `_<曲名>.txt` のように置き換える）
- 動作確認：`python3 scripts/serve.py 8765` で起動、`node --test` でローダー等のテスト、`node --check js/app.js js/loader.js js/progress.js` で構文チェック。実データの確認は `node scripts/check_media.mjs --base drive --round 第1回`（出力に答えを含むので貼らない）
